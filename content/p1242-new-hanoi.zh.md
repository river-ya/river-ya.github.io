## 先看直接移动为什么会判错

三根柱子上已有任意合法的起始布局，要输出到另一合法布局的**最短移动序列**。笔记的第一版递归只让最大盘从起点直达终点。这个做法总能构造合法解，却不保证步数最少。

只看三个盘就能发现差别。起初 3 号盘在 A，1、2 号都在 B；目标是 3 号到 B，1、2 号都到 A。

| 3 号盘走法 | 小盘怎样让路 | 总步数 |
| --- | --- | --- |
| A → B | 先把两只小盘从 B 搬到 C，移动 3 号，再从 C 搬到 A。 | 3 + 1 + 3 = 7 |
| A → C → B | 先移动 3 号，再把两只小盘从 B 搬到 A，最后移动 3 号。 | 1 + 3 + 1 = 5 |

## 先算“收拢一摞”的代价

盘的大小决定了同一根柱子上的相对次序，所以状态只需记下每个盘所在的柱子。用 `F(k, p, S)` 表示从布局 `S` 出发，把最小的 `k` 个盘全部收拢到柱子 `p` 的最少步数。

- `k = 0` 时返回 0。
- 若 `S[k] = p`，第 `k` 个盘已经就位，递归计算 `F(k − 1, p, S)`。
- 否则先把小盘收拢到第三根柱子 `q`，移动第 `k` 个盘，再整体搬回小盘。代价为 `F(k − 1, q, S) + 2^(k−1)`。其中后半项来自一次大盘移动和 `2^(k−1) − 1` 次整摞搬运。

每一步移动都可逆，因此“从一摞分散到目标布局”的代价，可以从目标布局反向调用同一个 `F`。

## 比较两条路线，再输出动作

找出起始和目标柱不同的最大盘 `k`。设它从 A 到 B，C 是第三根柱，`m = k − 1`，起始和目标布局分别叫 `S`、`T`。

| 路线 | 总代价 |
| --- | --- |
| 直接 A → B | `F(m, C, S) + 1 + F(m, C, T)` |
| 绕行 A → C → B | `F(m, B, S) + 1 + (2^m − 1) + 1 + F(m, A, T)` |

最大盘移动时，所有小盘必须在第三根柱子上。若最大盘绕一圈又回到原柱，小盘在这期间的合法动作本就可以在最大盘静止时完成，这一圈的大盘移动可以删去。因此只需比较表中两条路线。

`cost` 只计算步数，`move_gather` 才真正收拢小盘，`move_one` 每次打印一步并更新盘的位置。两条路线同长时，代码选择直接移动。输入最多有 45 个盘，比较候选方案时用 `1LL << m`，即使最优解很短，另一个候选代价也可能超过 32 位整数。
